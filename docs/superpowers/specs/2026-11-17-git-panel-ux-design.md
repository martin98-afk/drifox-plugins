# Git 面板体验与性能优化设计

## 目标与范围

对标 VS Code 内置源代码管理面板，保留左侧停靠形态和现有本地 Git、AI 提交能力。用户要求单人开发，不使用团队或子智能体。本轮不接 GitHub 登录、PR、Issues，不改宿主与其他插件。

## 已确认的交互设计

- 紧凑头部：源代码管理标题、刷新、更多、关闭；仓库名、可点击分支入口与 ahead/behind。
- 变更 / 历史切页。变更页放提交输入、AI 生成、提交模式和更改列表；历史页保留现有提交 Graph、详情、文件 Diff、更多历史能力。
- 已暂存的更改与更改独立分组，冲突单独分组或明确标记；同一路径可同时存在于暂存区和工作区。
- 更改支持列表 / 文件树切换，默认列表，记住选择。树只包含有更改的路径；目录展开状态跨刷新保留，文件名不换行撑高，完整路径由提示提供。
- 两种视图复用同一 Git 操作入口；支持选择、键盘移动、Enter 查看 Diff、右键完整菜单；单文件暂存/取消暂存可就地操作。列表渲染优先使用 Qt model/view，避免每个文件创建多个 QWidget。
- 分支入口提供新建、切换、删除；更多菜单保留 Stash 新建、列表、查看、应用、删除、Fetch、Pull、Push 和现有高级能力，不丢失破坏性操作确认。
- Diff 继续使用独立大弹窗，保留词级高亮、未跟踪文件预览、历史文件 Diff。
- 快捷提交支持 Ctrl/Meta+Enter；无暂存内容时主动作必须清楚表达实际提交模式，失败保留输入。
- 跟随宿主主题、字体与字号，检查 280/320/420px 侧栏、长路径、长分支、无仓库、空仓库与干净仓库。

## 数据与任务调度

- 每个后台读取任务捕获仓库路径、页面和请求版本，不从后台访问 QWidget 状态。
- 刷新请求合并；正在刷新时记录下一次刷新意图，不创建重叠刷新或丢掉用户请求。
- 写操作串行，读取与写入有明确互斥和完成后刷新；刷新期间用户操作可排队，不能静默丢弃。切换仓库后旧回调不得修改新仓库 UI。
- 线程存活到真正 finished 后才释放；隐藏停止周期刷新；销毁期间不阻塞等待网络任务，不跨线程销毁 QObject。
- 变更页只读状态与必要元信息；历史按需读取，分支/搁置通过菜单按需加载。无变化的数据不触发列表或历史重建。
- 可见时用低频定时检查并在操作后主动刷新；重开先显示已有快照再后台校验。刷新期间保留选择、滚动、树展开及历史展开。

## 验收

1. 先运行现有测试，记录基线及存量失败；新增回归测试覆盖列表/树数据映射、文件双区状态、重命名、冲突、刷新合并、旧请求回调隔离、线程释放与菜单操作入口。
2. 测量优化前后首次加载、无变化渲染、100/1000 文件渲染耗时；按相同环境与输入比较，不用静态分析替代数字。
3. Git 写入集成测试只在临时仓库执行，不改真实项目工作区。
4. 运行插件测试、定向 lint、离屏 UI 测试；真实宿主无法验证的交互明确标记，不声称已真机验证。
5. 同步插件 README。仅修改 git-panel 及本任务设计/计划文档，不碰 bili-scroll 现有变更，不自动发布或推送。
