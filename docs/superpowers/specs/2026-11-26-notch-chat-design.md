# 顶边快捷对话：首版规格

日期：2026-11-26

## 范围

新版独立插件，标识 `notch-chat`，不继承旧 `floating-chat` 的界面、实现或设置，不删除任何旧会话数据。首版仅支持 macOS、纯文本、单条独立多轮对话；不监控其他 DriFox 会话，不支持附件、工具与工具审批。对话归插件独立管理，不往主窗口当前会话插入消息。

## 交互

- 收起：屏幕顶部居中显示一枚胶囊，适配有无物理刘海的显示器。不显示标题、正文或跨会话计数。单会话状态为待机、等待回复、正在回复、完成、已停止或失败；文字和图标同时传达状态，不仅靠颜色区分。不抢焦点。
- 展开：沿用已确认的效果稿，顶部为状态与收起动作，中部为滚动对话，底部为固定输入区。点击或全局快捷键均可展开并聚焦输入；展开时再次按快捷键或按 Esc 收起，保留当前输入和在途回复。空闲时 Enter 发送、Shift+Enter 换行；中文输入法候选确认不得误发送。回复时可停止；同一时间只接受一轮请求。
- 快捷键：优先使用宿主现有可配置能力，先排查已占用组合。若宿主仅支持窗口内快捷键，验证 macOS 全局注册作为补充；注册失败时明确提示原因，保留点击胶囊入口。只在 DriFox 进程运行时提供服务。
- 完整会话入口：先核实宿主是否有受支持的独立会话保存和打开接口。有则链接到该会话；没有则隐藏入口，不能用切换主窗当前会话或写私有数据库代替。跨进程重启恢复不作为首版验收要求。

## 对话接入与失败处理

首选宿主 `engine.session`：仓库中已有插件调用 `create_engine_session` 并取得 `turn()` 结果。这只证明有调用样例，尚未证明当前宿主支持插件所需的增量回调及多轮输入。实施第一阶段在实际安装的 DriFox 中核对签名和线程要求，证明能拿到真实增量、复用同一条独立上下文、取消并收尾。若公开接口不满足，暂停并提出宿主补接口的最小范围；不回退旧私有引擎，不直接读 API 密钥或自建模型客户端，也不将完整结果切片冒充流式。

对话控制器与悬浮视图分离：请求在后台执行，界面在主线程更新；收起只切换视图。每次发送有独立轮次标识，取消、错误和超时要结束忙碌态，过期事件不写入后续轮次。能力缺失或模型请求失败时小窗显示可读错误并允许再次尝试，不记录请求正文和密钥到日志。

## 验收

1. 在运行的 DriFox 中切到另一应用，快捷键能够展开并将焦点给输入；Esc 收起且不打断对话。
2. 用已配置的真实模型发送「本次校验词是蓝松塔，请先只回复收到」，观察完整结果前已有真实增量；再问「刚才的校验词是什么」，回复包含「蓝松塔」。主窗原会话在两轮前后保持不变。
3. 发起一条较长回复，中途收起，重新展开后继续显示；停止后能再发，不串入已停止轮次的增量。
4. 模拟和实测分别标记。自动化覆盖状态、迟到回调和输入行为；真机截图核对收起和展开两态、深浅色及普通屏幕顶边位置。真实模型测试没有通过，不标记为可用。
