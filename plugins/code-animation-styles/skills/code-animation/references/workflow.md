# 工作流契约

六步，每步含输入、动作、可观察输出、转移条件、失败路线。

## 1. 需求确认

- **输入**：用户的一句话或一段材料
- **动作**：确认内容与时长、横竖屏、镜头走法、多风格衔接顺序、**配乐音效有无**
- **输出**：一份明确的需求清单（用户可确认）
- **转移**：清单齐备 → 步骤 2；用户答不上来 → 给默认建议（横屏 1080p、30–60 秒、无声或轻音效）并声明假设
- **失败路线**：用户只有模糊主题 → 先按步骤 2 挑 2–3 个候选风格给用户看静帧，用画面反向收敛需求

## 2. 挑风格

- **输入**：需求清单
- **动作**：读 `styles/INDEX.md`，按「适合/关键词」列匹配；拿不准就读候选风格的 `.jpg` 静帧对比
- **输出**：选定风格编号（1 个）或衔接序列（2–3 个 + 顺序）
- **转移**：用户确认 → 步骤 3；用户想自己挑 → 降级（让用户开 `styles/风格挑选.html`，回传勾选清单后进步骤 3）
- **失败路线**：INDEX 无匹配 → 换同义词再筛 → 仍无则如实告知库不覆盖，提议最接近的风格让用户定夺，禁止编造风格编号

## 3. 取提示词

- **输入**：风格编号
- **动作**：读 `styles/风格提示词/<分类>/<编号>_<名称>.md` 全文；A–G 系列同时记下依赖的 `_公共函数.js` 工具函数
- **输出**：风格提示词全文（含参考实现代码，如有）
- **转移**：拿到全文 → 步骤 4
- **失败路线**：文件不存在（编号来自旧索引）→ 回 `styles/INDEX.md` 核对编号

## 4. 合成生成任务

- **输入**：风格提示词 + 需求清单
- **动作**：按 `references/prompt-craft.md` 的分寸合成任务：填实 `{{ }}` 占位符、内联公共函数、写死颜色/时间/镜头、写明配乐音效方案
- **输出**：一份完整生成任务描述
- **转移**：自查占位符与时长无遗漏 → 步骤 5
- **失败路线**：风格提示词与需求冲突（如风格是竖版海报、用户要横屏）→ 优先用户需求，改写冲突项并在交付时声明改动点

## 5. 生成 html

- **输入**：生成任务
- **动作**：产出单文件 html（内联 CSS/JS/音频），浏览器直接打开即可播放
- **输出**：html 文件路径
- **转移**：通过步骤 6 自查 → 交付用户预览
- **失败路线**：动画跑不起来 → 优先查控制台报错、公共函数漏内联、时间轴单位（秒/帧）混用

## 6. 自查与交付

- **输入**：html
- **动作**：自查四项——无控制台报错；时间轴符合约定时长；`{{ }}` 全部填实；要求了配乐则真实有声
- **输出**：交付说明（风格编号、时长、如何打开、无声原因如适用）
- **转移**：用户认可 → 结束；用户要 mp4 → 协商 ffmpeg 屏幕录制/逐帧导出路线，不默认承诺
- **失败路线**：用户不满意风格 → 回步骤 2 换风格，已生成的 html 保留作对比
