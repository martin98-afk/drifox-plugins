# 会议纪要（meeting-notes）

语音会议转录 + AI 纪要 + 本地会议管理。整页卡片，左侧会议列表，右侧实时转写与纪要。

## 入口

- 标题栏常驻 tab「会议」
- 命令 `/meeting-notes`

## 用起来是什么样

1. 左栏「+ 新建」建一场会议（也可以不建，直接点录音会自动建）；「导入音频」可把已有录音导入成一场会议并识别（wav/m4a/mp3/aac/flac/ogg 等）。macOS 用系统自带 `afconvert` 转码，无需安装任何东西；Windows 需装有 ffmpeg。音频文件也可以直接**拖到左栏列表区**，边框高亮后松手即导入成新会议；一次一个，多文件只取第一个
2. 点右侧圆形按钮录音，每 20 秒切一片上传识别，转写实时追加（带时间戳与说话人）
3. 圆形按钮在录音中变成暂停，暂停中变成继续；旁边的「结束」收尾本次录音
4. 录音是**往当前会议里追加**：已结束的会议再点录音，新内容接在旧转写之后
5. 录音中每攒够 10 分钟，后台自动把这段精转一次；结束会议只精转最后一段尾巴
6. 转写完成后自动生成纪要（概要 / 关键讨论 / 决议 / 待办 / 风险），走系统配置的模型
7. 双击标题就地改名，点说话人徽章改真名；右上角 ⋯ 可导出 Markdown、定位录音文件、删除

## 配置（设置 → 会议纪要配置）

| 项 | 说明 |
|---|---|
| 配置来源 | 下拉选主程序「服务商设置」里的语音识别实例，每个实例再展开到具体模型；选中后端点/Key/模型以它为准，优先级高于下面两项 |
| 硅基流动 API Key | 留空时自动复用「语音输入」插件的 Key |
| 识别模型 | 默认 `XingChenASR-Diarize-V3.0`（免费，带说话人分离） |
| 切片时长 | 默认 20 秒。越短越实时，请求越频繁（免费模型有限流） |
| 保留录音文件 | 关闭则会议结束即删 WAV，只留文字 |
| 纪要模型 | 下拉选已配置的服务商/模型；首项「跟随当前对话模型」 |
| 纪要提示词 | 内置模板直接铺在框里，可改；`{transcript}` 代表转写稿 |

模型价格（硅基流动）：XingChen ASR 系列与 SenseVoice 免费；`Qwen/Qwen3-ASR-1.7B` 约 ¥0.00022/秒（≈0.79 元/小时）。

## 数据位置

一场会议一个文件夹，文件夹名就是会议名（重名自动加 ` (2)`，改名时文件夹跟着改）：

```
<app_data>/plugin_data/meeting-notes/
└── 产品评审会/
    ├── meeting.json     转写 + 纪要 + 说话人命名
    └── audio.wav        会议录音（16kHz/16bit/单声道）
```

可以直接在文件管理器里按名字找会议、拷走、备份。右上角 ⋯ →「打开录音位置」可定位到当前会议的 WAV。
旧版本的 `meetings/<id>.json` + `audio/<id>.wav` 首次启动会自动迁移。

## 实现要点

- **采集**：分片录音。Windows 用 winmm MCI，macOS 用 AVFoundation（ctypes 直调，零第三方依赖）。每片 stop → 立刻重开设备，缺口约 50~100ms。
- **导入转码**：macOS 走 `/usr/bin/afconvert`（系统自带，GUI 宿主极简 PATH 也能看到，零依赖零许可）；其从 AAC 解码产出的 WAVE_FORMAT_EXTENSIBLE 头会被改写成标准 PCM，供标准库 `wave` 读取。Windows 走 ffmpeg 并加 `CREATE_NO_WINDOW` 避免闪黑窗；两者都没有时只接受 16bit WAV。
- **转写渲染**：整页刷新复用已有行对象逐段改数据，不销毁重建（600 行实测 330ms → 1ms）；说话人改名只更新匹配徽章，不全页重绘。
- **识别**：`/v1/audio/transcriptions` multipart 上传，串行队列（并发会撞免费模型限流），失败退避重试 2 次。
- **识别配置优先级**：配置项 `host_provider` 选中的宿主实例（`model.config_for` + `capability_type=speech_recognition`，取其 `API_URL`/`API_KEY`/`模型名称`）> 本插件自填 Key > 复用 voice-input 的 Key。宿主未选、实例失效或旧宿主忽略 `capability_type` 时逐级回退，最终落到内置硅基流动端点，行为与接入前一致。
- **说话人**：Diarize 模型返回 `segments[].speaker`。分片之间编号不自洽，所以录音中每攒够 10 分钟精转一段、结束时再转最后的尾巴（增量精转，每次只重识别一段音频，替换该时间段的实时结果）。
- **纪要**：宿主 `engine.session` + 当前（或指定）模型，插件不单独保存 LLM 密钥；模型输出首行的 `# 标题` 会顺带写成会议名。

## 平台支持

| 平台 | 录音 | 依赖 |
|---|---|---|
| Windows | winmm MCI（ctypes） | 无 |
| macOS | AVFoundation（ctypes） | 宿主 Info.plist 需声明麦克风权限 |
| Linux | arecord | 系统需装 alsa-utils（未实机验证） |

导入音频、转写、纪要、存储在所有平台都能用（纯标准库处理 WAV）。插件零第三方 pip 依赖。

## 已知限制

- 切片时设备重开有约 50~100ms 缺口
- macOS 导入非 WAV 由系统 `afconvert` 转码（无需额外安装）；Windows 仍需 ffmpeg，没装时只支持 16bit WAV（立体声自动下混）
- 打包版宿主是 GUI 进程，PATH 极简，`brew install ffmpeg` 装到 `/opt/homebrew/bin` 也不会被 `which` 找到；这是 macOS 改用绝对路径调 `afconvert` 的原因
- 免费模型有限流，撞 429 会重试；重试仍失败的片会跳过并提示，不中断录音
- 说话人编号在每段 10 分钟精转内自洽，跨段不做身份对齐
