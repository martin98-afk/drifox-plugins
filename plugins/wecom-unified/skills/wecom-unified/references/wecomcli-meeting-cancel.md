# 操作参考：取消会议

取消已创建的会议。**写操作**，参数就绪后直接执行。不预先按"是否本人创建"拦截，能否取消由接口返回结果判断。**周期会议支持取消**，通过是否传 `sub_meeting_id` 指定取消范围（见下文「[周期会议取消](#周期会议取消)」）。

## 命令

```bash
wecom-cli meeting cancel --json '{...}'
```

## 请求参数

| 字段             | 类型   | 必填 | 说明                                |
| ---------------- | ------ | ---- | ----------------------------------- |
| `meeting_id`     | string | 是   | 会议 ID（来自 `list`/`search` 返回的 `meeting_id` 字段，长字符串，非 9 位会议号） |
| `sub_meeting_id` | string | 否   | 子会议 ID，**周期会议专用**：传 = 仅取消该场次，不传 = 取消整个系列。取值只能来自 `list`/`search` 的真实返回值，**禁止编造**；非周期会议不传 |

**返回**：成功时返回空对象 `{}`，这是正常结果，不代表失败。收到空对象即可告知用户取消成功。

## 周期会议取消

周期会议（`is_repeat_meeting=true`）整个系列共用一个 `meeting_id`，取消范围由**是否传 `sub_meeting_id`** 决定：

| 用户诉求 | 入参 | 实际影响 |
|---|---|---|
| "就这次不开""最近那场取消" | `meeting_id` + 该场 `sub_meeting_id` | 仅该场次，后续场次不受影响 |
| "以后都不开了""这个周会不要了""全部取消" | 只传 `meeting_id` | 整个系列 |

**只能取消「最近一场」或「整个系列」[CRITICAL]**

`sub_meeting_id` 只能取自 `list` / `search` 返回，而它们对一个周期系列**只返回最近要开的那一场**、不展开全部场次。因此"仅取消这一次"实际只作用于**最近的那一场**：

- 用户要单独取消系列**中间的某一场**（非最近一场）时，如实告知目前只能取消最近的一场（**必须给出该场日期**）或整个系列，让用户在这两者中选择，或引导其在企业微信客户端操作。
- **禁止拿最近一场的 `sub_meeting_id` 顶替用户指定的其他场次**——会取消错场次，属不可逆误操作。
- **禁止编造 `sub_meeting_id`**，也禁止用周期规则推算出的场次（推算结果没有真实 `sub_meeting_id`）。

**取消范围必须由用户拍板**

取消不可逆，两种范围差别极大，禁止自行默认。用户已明确（如"就这次不开""以后都不开了"）时直接映射、无需追问；未明确时用文字询问，**选项里带上最近一场的具体日期**：

```
这是周期会议，要取消哪些？（请回复：仅取消最近一场（9月15日 16:00） / 取消整个系列）
```

## 约束

- **不预先按"是否本人创建"拦截取消**，直接执行 `cancel`，能否取消由接口返回结果判断：返回空对象 `{}` 即成功；返回权限类错误则说明当前用户无权取消，告知用户并建议联系会议发起人
- **周期会议取消须先定范围**：检测到目标为周期会议（`search`/`list` 返回 `is_repeat_meeting=true`）时，先确定取消范围再执行，范围不明确时必须询问用户（详见「[周期会议取消](#周期会议取消)」）
- **取消会议后，其关联日程会被一并取消，禁止再对同一场调用 `schedule cancel`**；模糊取消时若同一场（主题+时间一致）在会议和日程两边都命中，只走 `meeting cancel` 一次即可

## 定位目标时的跨载体消歧（模糊取消）[REQUIRED]

用户说"取消那个会 / 取消 xx 会 / 取消 xx 会议 / 把那个会取消掉"等模糊表述、未明确是日程还是在线会议时，**不要只在会议里找**——「会」可能是含在线会议链接的会议，也可能是一条纯日程，只查一边会漏定位：

- **明确是在线会议**（提到入会链接 / 会议号 / 视频会议 / 腾讯会议 / 远程参会等专属特征）→ 只在本技能 `meeting search`/`list` 定位，走 `meeting cancel`。
- **明确是日程 / 安排**（说的是"日程 / 安排 / 我的日历"且不带在线会议特征）→ 改用 `读取 wecomcli-calendar.md` 在日程里定位并 `schedule cancel`。
- **模糊无法判定** → 会议和日程**两边都查**：本技能 `meeting search`/`list` + `读取 wecomcli-calendar.md` 用同样关键词 / 时间查日程，合并候选、按"主题 + 时间"去重（同一场两边都命中只保留一条），再用文字让用户**选定要取消的唯一一条**；选定后按其归属路由——是会议（或两边都命中的同一场）→ `meeting cancel`（会连带取消关联日程）；是纯日程 → 改用 `读取 wecomcli-calendar.md` 走 `schedule cancel`。

> **与查询消歧的区别**：查询时可以两边都查、都展示；但取消是**写操作，绝不能两边都直接取消**，模糊时必须先让用户确认唯一目标，再执行对应的 cancel。

## 工作流

```
用户发起取消意图
    |
    +-- 定位目标会议
    |   +-- 有关键词 → meeting search（不追问时间）
    |   +-- 有时间信息 → meeting list 按时间范围查询
    |   +-- 都没有 → 用文字询问引导用户补全缺失的参数
    |
    +-- 匹配结果处理
    |   +-- 唯一匹配 → 继续
    |   +-- 多条匹配 → 用文字让用户选择：
    |   |     文字提问："找到多个匹配会议，请选择要取消的一个："
    |   |     列出候选（如"项目评审 - 4月8日 14:00 / 项目评审 - 4月15日 14:00"，最多 4 条；超出时展示前 4 条并提示用户缩小关键词）
    |   +-- 无匹配 → 建议修改关键词或扩大时间范围重试
    |
    +-- 状态检查（不做"是否本人创建"的前置拦截，直接进入状态/周期判断）
    |   +-- meeting_status = "init"（待开始）→ 继续
    |   +-- meeting_status = "started"（进行中）→ 告知用户会议正在进行中，无法取消；终止流程
    |   +-- meeting_status = "end"（已结束）→ 告知用户会议已结束，无需取消；终止流程
    |
    +-- 判断是否周期会议（优先用定位阶段 search/list 已返回的 is_repeat_meeting，无需额外调 get；
    |     仅当定位结果里没有该字段时才补一次 meeting get 看 repeat_rule）
    |   +-- 非周期会议 → 直接执行 cancel（只传 meeting_id）
    |   +-- 周期会议 → 先确定取消范围
    |         +-- 用户已明确"就这次/最近那场" → 传 meeting_id + 该场 sub_meeting_id
    |         +-- 用户已明确"以后都不开了/全部取消/不要了" → 只传 meeting_id（整个系列）
    |         +-- 用户指定的是中间某一场（非最近一场）→ 不执行，如实告知只能取消最近一场
    |         |     （给出该场日期）或整个系列，让用户二选一；禁止拿最近一场顶替
    |         +-- 范围不明确 → 用文字询问：
    |               "这是周期会议，要取消哪些？（请回复：仅取消最近一场（<该场日期时间>） / 取消整个系列）"
    |
    +-- 执行 cancel（不论会议由谁创建，都直接执行，不提前拒绝）→ 依返回结果判断：
          +-- 返回空对象 {} → 取消成功，周期会议须说明实际取消范围（"已取消 9月15日 那一场" / "已取消整个周期系列"）
          +-- 返回权限类错误 → 说明当前用户无权取消该会议，告知用户并建议联系会议发起人
```

### 异常路径

| 异常情况 | 处理方式 |
|---------|---------|
| 接口返回无权取消（非发起人） | 直接执行 cancel 后依返回判断；返回权限错误时告知用户无权操作, 建议联系会议发起人 |
| 会议已结束 | 告知用户该会议已结束, 无需取消 |
| 会议进行中 | 告知用户该会议正在进行中, 无法取消 |
| 用户要取消周期系列中间的某一场 | 拿不到该场 `sub_meeting_id`，如实告知只能取消最近一场（给出日期）或整个系列，二选一；或引导其在企业微信客户端操作。禁止拿最近一场顶替，禁止编造 `sub_meeting_id` |
| 取消接口返回错误 | 检查 meeting_id 是否正确, 确认权限后重新尝试 |
| 找不到目标会议 | 建议通过搜索或列表重新定位, 参见 [meeting-search](wecomcli-meeting-search.md) |

## 示例请求

**取消单次会议 / 取消整个周期系列**（都只传 `meeting_id`）：
```json
{
  "meeting_id": "<meeting_id>"
}
```

**取消周期会议的最近一场**：
```json
{
  "meeting_id": "<meeting_id>",
  "sub_meeting_id": "<sub_meeting_id>"
}
```

## 典型场景

### 1. 取消普通会议

```
用户：帮我取消明天的项目评审会
→ 调用 meeting search（keywords=["项目评审"]）
→ 找到 1 条 → 调用 meeting get 获取详情
→ meeting_status = "init"（可取消），非周期会议
→ 调用 cancel（不做是否本人创建的前置拦截）→ 返回 {} → 告知已取消
```

### 2. 取消周期会议

```
用户：这周的周会不开了
→ meeting search（keywords=["周会"]）→ 周期会议（is_repeat_meeting=true）
  拿到 meeting_id 与最近一场的 sub_meeting_id（9月15日 16:00）
→ "这周不开" = 仅这一场 → 传 meeting_id + sub_meeting_id → 返回 {}
→ 报告：已取消 9月15日 16:00 那一场，后续场次不变

用户：以后的周会都不用开了
→ 诉求是"这个会不办了" → 只传 meeting_id → 返回 {} → 报告：已取消整个周期系列

用户：把周会取消了                        ← 范围不明确
→ 询问：这是周期会议，要取消哪些？（请回复：仅取消最近一场（9月15日 16:00） / 取消整个系列）
→ 按用户回答执行
```

### 3. 用户要取消中间某一场（做不到，如实告知）

```
用户：把 9月17日 那次周会取消掉
→ 定位到周期会议，list/search 只返回最近一场（9月15日 16:00），拿不到 9月17日 的 sub_meeting_id
→ 不执行 cancel，也不拿 9月15日 的 sub_meeting_id 顶替
→ 告知：目前只能取消最近的一场（9月15日 16:00）或整个系列，无法单独取消 9月17日 那场。
  你可以选其中一种，或在企业微信客户端里单独取消 9月17日 那场。
```

### 4. 无权取消（由接口返回判断）

```
用户：帮我取消张三组织的评审会
→ 找到目标会议 → 不因非本人创建而提前拒绝，直接调用 cancel
→ 返回权限错误 → 告知用户：您没有该会议的取消权限，建议联系发起人张三操作。
```
