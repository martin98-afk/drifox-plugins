# Doc Coauthoring 技能 — 协作写作三阶段

源自 [anthropics/skills/doc-coauthoring](https://github.com/anthropics/skills/tree/main/skills/doc-coauthoring)。

## 何时触发

- 写技术文档、规范文档、决策文档
- 团队协作写作
- 需要结构化访谈 + 迭代精炼

## 3 大阶段

### 阶段 1：起草（Drafting）

```
1. AI 提 5-10 个开放问题
2. 用户回答
3. AI 生成第一稿（草稿）
4. 标记不确定之处
```

### 阶段 2：迭代（Iterating）

```
1. 用户审阅草稿
2. AI 提问澄清模糊点
3. 标记所有未决决策
4. 精炼 + 改进
```

### 阶段 3：定稿（Finalizing）

```
1. 一致性检查
2. 完整性检查
3. 语法校对
4. 输出最终版本
```

## 5 类文档模板

### 1. PRD（产品需求）

```
1. 问题陈述
2. 目标用户
3. 核心功能
4. 成功指标
5. 范围/非范围
6. 时间线
7. 风险
```

### 2. RFC（设计提案）

```
1. 摘要
2. 动机
3. 详细设计
4. 取舍
5. 部署计划
6. 备选方案
```

### 3. 设计文档

```
1. 背景
2. 目标
3. 架构
4. 数据模型
5. API 设计
6. 测试计划
7. 风险
```

### 4. 决策记录（ADR）

```
1. 标题
2. 状态
3. 上下文
4. 决策
5. 影响
```

### 5. 复盘文档

```
1. 背景
2. 目标
3. 结果
4. 学到什么
5. 下一步
```

## 5 个最佳实践

### 1. 结构化访谈

每次只问 1 个问题，避免多问题。

### 2. 标记未决

```markdown
> ⚠️ 待定：用户角色还需澄清
```

### 3. 风格统一

- 第一人称 vs 第三人称 → 选一个
- 主动 vs 被动 → 主动
- 简洁 vs 详细 → 简洁

### 4. 版本控制

```markdown
v0.1 - 起草
v0.5 - 内部评审
v1.0 - 定稿
```

### 5. 决策追踪

决策应可追溯：谁、何时、为什么。

## 5 个反模式

- ❌ **跳过访谈直接写** — 错过上下文
- ❌ **一次写完** — 应当迭代
- ❌ **不标未决** — 后续无法追溯
- ❌ **风格不一致** — 多种语气混用
- ❌ **不审校** — 语法错误
