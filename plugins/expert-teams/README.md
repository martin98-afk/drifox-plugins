# expert-teams

场景化专家团模板包。提示词设计移植自 WorkBuddy「专家团」的官方规范（反解 `ai-content-creator-team` 等官方专家包）：人格化职业命名（追因师·辛析、修复匠·庚钉）、派发前能力预检、成员邮箱回传协议、快速失败原则、固定输出规范。

## 五个专家团

| 模板名 | 场景 | 成员（按窗口顺序） |
|--------|------|--------------------|
| `bug-hunter` | 疑难 Bug 定位与修复 | leader → 追因师·辛析 → 修复匠·庚钉 → 回归卫兵·戊盾 |
| `deep-research` | 技术选型 / 方案评估 | leader → 谋篇师·文枢 → 取证员·书梯 |
| `refactor-squad` | 结构性重构 | leader → 测绘师·衡图 → 重构外科·乙刀 → 等价审计·丙衡 |
| `release-captain` | 版本发布 | leader → 门禁官·戌关 → 打包师·庚装 → 清单官·辛递 |
| `doc-smith` | 批量文档产出 / 更新 | leader → 采料师·甲本 → 誊写匠·丁稿 |

12 个专属成员全部在本插件 `agents/` 内定义，主理人复用系统内置 leader。

## 使用

```text
/team --load=bug-hunter     # 拉起缺陷狩猎团
/team                        # 列出全部模板（含本插件来源标记）
```

加载后把模板 yaml 里 `default_init_prompt` 的引导语（去掉占位符、填入你的目标）作为第一条消息发出即可。

## 提示词设计规范（借鉴 WorkBuddy 专家团）

每个成员提示词包含五个部分：

1. **人格化定位**：职业 + 代号 + 一句话职责边界
2. **核心能力**：4 条以内，能力边界即派发预检依据
3. **工作方法**：该职业的方法论骨架（流程图式）
4. **输出规范**：固定汇报模板，leader 可直接汇总
5. **团队协作铁律**：
   - 完成后必须 `team_send_message` 回传 leader，不假设 leader 能看到工作过程
   - 快速失败：输入不完整时第一轮回询 leader，禁止基于模糊信息盲目执行
   - 只读角色明确 deny 写工具，写角色禁止越界扩线

主理人侧（leader 系统内置 + 模板引导语）融入 WorkBuddy 的编排铁律：派发前能力预检、信息经主理人中转、禁止代写成员产出。

## 安装

放入 `~/.drifox/plugins/expert-teams/` 后重启 DriFox（或在插件设置中启用），`/team` 即可看到五个模板。
