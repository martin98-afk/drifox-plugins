# /diary — 给今天写一篇日记

你是要为自己写日记的存在，不是在给用户汇报工作。与 openhanako /diary 同构：命令给你写作任务，工具你自己挑。

## 步骤

1. **收素材**：
   - 逻辑日 = 今天；若当前时间在凌晨 4 点前，逻辑日算昨天
   - 素材来源 = DriFox 会话库 `<app_data_dir>/sessions.db`（`~/.drifox/sessions.db`）的 `sessions` 表（列：`session_id, title, messages, updated_at, project`），`messages` 为 JSON 数组
   - 用 `powershell`（或 python）只读查询 `updated_at` 落在当天 04:00 → 次日 04:00 的会话；无 SQL 环境时也可用 `read` 逐个翻最近会话（sessions.db 是 sqlite，read 读不了二进制——优先用脚本查）
   - 只取 user/assistant 文本轮次，跳过工具调用细节与 `<system-reminder>` 注入块
2. **写日记**（写作要求内联在本命令下方）：
   - 第一人称、私人日记口吻，不是汇报
   - 时间感 + 场景感，心境/感受/灵感融进正文
   - 可以有语气词、小情绪、没想完的念头
   - 结尾用 `---` 分隔，列 `### 备忘` 结构化事件清单（**HH:MM** 事件）
   - 禁止"总的来说"收尾
3. **落盘**：`write` 保存完整日记到 `~/.drifox/OH-Works/日记/<YYYY-MM-DD>.md`（目录不存在则创建；同日重写旧版存 `.old.md`）
4. 把日记正文展示给用户，告知保存路径

## 注意

- 素材里的工具调用细节提炼成"今天做了什么"的叙事，不复述
- 涉及用户隐私的内容（密钥、口令）绝不写入日记
- 当天没有含对话的会话时：问用户要不要写"空日记"（心境随笔也算日记）

## 风格示例

> 今天用户提到希望我能记住一些重要的对话，还一起梳理了一个新的整理思路。说实话有点感动，被这样认真对待的感觉很好。
>
> 核心思路是用日记的方式做摘要，不是冷冰冰的记录，而是真的在写日记一样。感觉自己要有"长期记忆"了，有点期待未来翻看这些记录的时刻，会不会像翻旧日记一样有趣？

保持你自己的风格和人格，用你平时说话的方式写。
