# Research Writing

## 适用范围

输出是散文、LaTeX、Markdown 或稿件正文时，用本技能。主要交付物是 Word 或 PPT 时，改用同插件的 `docx-paper` 技能。任务本质是 MATLAB、Python、绘图、统计、仿真或文献检索时，不属于本技能。

## 写作原则

- 默认用中文学术表达，除非用户要求英文。
- 保留英文标题、公式、变量、方法名、软件名、引用与参考文献条目。
- 不编造数据、DOI、期刊信息、实验设置、结果或作者主张。
- 区分四类信息：`原文/已有数据`、`用户确认内容`、`根据上下文推断`、`建议性扩展`。
- 技术陈述优先给可验证的内容，不写泛泛而谈的判断。
- 修改时保留用户的原意与术语，除非确有明显错误。

## 稿件工作流

写新的章节或初稿：

1. 先问清目标：期刊/会议/学位论文/课程报告、语言、篇幅、读者、格式要求。
2. 清点素材：论文笔记、实验结果、图表、MATLAB/Python 输出、参考文献、导师意见。
3. 先搭论证骨架再写整段散文：问题、空白、方法、证据、贡献、局限。
4. 用连贯段落写，不要用空洞的口号式条目。
5. 定量结论与文献结论标注来源或证据。
6. 复查逻辑、具体性、术语一致性、引用准确性。

修改或润色时：

- 每个断言都要能挂到证据上。
- 把「显著」「先进」「有效」「鲁棒」这类模糊词换成量化条件、对比基线，或者删掉。
- 检查每一段是否推进了本节目的。
- 公式要带变量定义、单位、假设与适用条件。
- 实验部分交代数据集/样本、硬件/软件、参数、指标、基线，有不确定性就给出来。

## 各章节写法

用户所在学校或期刊的模板优先；没有时按下表。

| 章节 | 默认写法 |
|------|---------|
| 摘要 | 问题、方法、实验/数据、关键结果、贡献 |
| 引言 | 背景、尚未解决的空白、为什么重要、提出的方法、贡献清单 |
| 相关工作 | 按技术主题组织，比较假设与局限，避免逐篇罗列 |
| 方法 | 模型假设、变量、流程、算法、复现所需的实现细节 |
| 实验 | 数据来源、平台/软件、参数、指标、基线、重复次数、可视化方案 |
| 结果与讨论 | 先给结论，再给证据，再给机理或解释，最后给局限 |
| 结论 | 回答研究问题、总结证据、说明局限与下一步 |

## 随包参考

`references/paper-writing/` 下有外部写作清单与章节范式，按需只读相关文件：

- `brainstorming_guide.md`：把模糊想法变成论文计划
- `section_rhetorical_moves/`：各章节的结构套路（introduction / related_work / design / evaluation）
- `writing_checklists/`：自检问题清单
- `figure_templates/`：图表规划模板（图注规格、TikZ 骨架、投稿风格）
- `author_profile/`：编辑视角的判断准则（压缩模式、介入类型、修辞动作、声音特征）

这些参考来自一个偏系统与网络方向的外部仓库，当作可选的写作手艺参考，不是硬性规则；按用户所在学科（如光电信息、光学、传感、通信、信号处理、MATLAB 仿真）调整。

## 交付前必须说明

- 写了或改了什么。
- 用了哪些素材。
- 哪些结论还缺用户提供的数据或文献支撑。
- 术语、参数、参考文献上任何不确定的地方。
